# PHASE 3: LLM-Based Tool Input Extraction — Executive Summary

## Problem Statement

The tool infrastructure (4 tools, ToolRegistry, tool_executor_node) is complete but NON-FUNCTIONAL because:

1. LLMRoutePlanner._parse_llm_response() (line 112) sets: tool_inputs_hint = {}
2. LLMRoutePlanner._heuristic_fallback() (line 139) sets: tool_inputs_hint = {}
3. tool_executor_node receives empty inputs
4. Tool validation fails: "Missing required field: issuer_market_cap" etc.
5. NO TOOLS EVER EXECUTE

Current consequence: All tool-based queries fail with validation errors.

## Solution Architecture

Three-layer extraction strategy:

### Layer 1: LLM-Based (Primary)
- Enhanced system prompt requests tool_inputs_hint field
- LLM extracts numeric values, classifications from query text
- Enable: Full tool functionality with natural language

### Layer 2: Heuristic (Secondary)
- QueryParser: extract numbers, currency, percentages, types
- SizeTestInputExtractor: keyword matching + adjacent numbers
- Benefit: Offline, no LLM needed

### Layer 3: Recovery (Tertiary)
- tool_executor_node attempts extraction on validation failure
- Graceful degradation with user feedback
- Maximize success rate
