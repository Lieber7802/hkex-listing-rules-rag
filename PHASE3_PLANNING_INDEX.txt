KEY PROBLEM
===========

Current State:
- Tool infrastructure complete (4 tools, ToolRegistry, tool_executor_node)
- BUT tool_inputs_hint is ALWAYS empty {} (line 112, line 139 in llm_route_planner.py)
- Result: ALL tool executions fail validation
- No tools ever execute

Why:
  User Query
    → LLMRoutePlanner._parse_llm_response() sets tool_inputs_hint = {}
    → tool_executor_node receives {}
    → Validation fails: "Missing required field..."
    → Tool never runs

SOLUTION: 3-LAYER EXTRACTION
=============================

Layer 1: LLM-Based (Primary)
  - Enhanced prompt requests tool_inputs_hint
  - LLM extracts from query text
  - Fallback if unavailable

Layer 2: Heuristic (Secondary)
  - Regex + keyword matching
  - No LLM dependency
  - Fast, deterministic

Layer 3: Recovery (Tertiary)
  - Retry extraction on validation failure
  - Graceful degradation
  - Transparency via extraction_log

QUESTIONS?
==========

Q: Why not just use LLM for everything?
A: LLM can fail (unavailable, inconsistent). 3 layers provide redundancy.

Q: Won't heuristic extraction be inaccurate?
A: Yes, but better than 0% (current). Layer 1 handles 80%, 2-3 catch rest.

Q: What about Chinese queries?
A: Minimal support Phase 3. Phase 4 dedicated i18n work.

Q: How much slower?
A: <100ms per query (regex only, O(1) operations).
